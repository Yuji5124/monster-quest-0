# モンスタークエスト0 戦闘仕様

最終更新: 2026-09-22 JST

このファイルは戦闘システム・ボス攻略・数値管理の正本。最終バランス値は `TBD_REGISTRY.md` に従い、根拠なく確定しない。

## 1. 基本
- 昔ながらのコマンド式RPG戦闘。
- 通常戦闘で経験値・所持金を得てレベルアップする。
- 草原・森・洞窟等のエリアごとにエンカウントテーブルを持つ。
- ボス戦は単純なレベル勝負だけでなく、少ないヒントから攻略法を見つける遊びを入れる。
- 初見約4時間30分 / 寄り道込み約5時間30分の作品として過度なレベル上げを要求しない。

## 2. 基本コマンド
最低限:
- こうげき（2026-09-14ユーザー指定の表示名。内部ID `fight` は維持）
- まほう
- どうぐ
- にげる

必要に応じて防御等を追加する場合はユーザー確定後に正式化する。

## 5. だいヒット
- 一般的な「クリティカル」という表示は使わない。
- 正式戦闘メッセージは **「だいヒット」**。
- 発生率・倍率はTBD。

**2026-09-23実装（TEMP_TEST_VALUE）**: `BattleSystem.ts`の`DAI_HIT_RATE`(1/16)・`DAI_HIT_MULTIPLIER`(1.5倍)で、
物理攻撃(`kind: "attack"`、パーティ・敵の双方)にだいヒット判定を追加した。発生時は通常ダメージへ
倍率をかけ、戦闘メッセージへ「だいヒット！」を追加する。「クリティカル」「会心」の内部表記は使わない。
発生率・倍率は引き続きTBDであり、この値は最終値ではない。

## 6. わたべ
- わたべは主要3人パーティとは別の特殊参加キャラクター。
- 固有攻撃 **「とくだいヒット」** を使用できる。
- 通常の「だいヒット」より強い特別な攻撃として扱う。
- **「もういちど」以降のオロチゾンビ再戦／最終解決に関わる。**
- 最終倍率はTBD。

**2026-09-23実装（TEMP_TEST_VALUE）**: `BattleSystem.ts`の`canUseTokudaiHit`フラグを持つ戦闘者だけが
`TOKUDAI_HIT_RATE`(1/8)・`TOKUDAI_HIT_MULTIPLIER`(2.5倍、だいヒットより高倍率)でとくだいヒットを
発動できるようにした。だいヒットの名称変更ではなく独立した判定・メッセージ(「とくだいヒット！！」)を持つ。
わたべ自身はまだプレイアブルキャラクターとして未実装(`PartySystem.PARTY_MEMBER_IDS`はhero/tarosa/mireiのみ)
のため、現状どの正式パーティメンバーにも`canUseTokudaiHit`は設定していない(戦闘内部ロジックのみ用意)。
取得方法・最終発生率・最終倍率はTBD。

## 7. 戦闘不能・回復
- HPが0になったキャラクターは戦闘不能。
- `ライフ` は回復系魔法として扱う。
- `リライフ` はMQ0内では戦闘不能からの復活魔法として採用する。
- 原作でのリライフの意味は未確定のため「原作確定情報」と混同しない。
- 通常全滅時の最終ペナルティ・復帰地点はTBD。
- **オロチゾンビ1回目の失敗／異常遷移は通常全滅処理と分離し、`GLITCH_SPEC.md` のストーリーイベントとして扱う。**

### 7.1 状態異常「毒」（2026-09-22実装）
- `BattleCombatant.status.poisoned`で管理し、ターン終了時（全パーティ行動後・敵行動後）に
  最大HPの5%前後（TEMP_TEST_VALUE、最小1）のダメージを与える。
- `statusResistance.poison`で敵ごとに無効化できる（バトラスは無効化しない）。
- 付与はタロサの武器アクション(`weaponAction.statusEffect`)など、通常攻撃に乗せる形で実装した。
- どくけし(`ITEM_DEFINITIONS.dokukeshi`)を戦闘中に使うと解除できる。
- バトラス固有のコードをBattleScene/BattleSystemへ直書きせず、敵データ側の
  `statusResistance`・武器データ側の`weaponAction`で表現する（§13の実装禁止方針どおり）。

### 7.2 パーティの複数アクター行動（2026-09-22実装）
- `BattleSystem`は1〜3人のパーティを受け付ける。生存中の全メンバーが1人ずつコマンドを
  入力してから、敵が1回行動する（行動順は素早さ基準ではなくパーティ内の固定順。§3のとおり
  最終式はTBD）。
- 戦闘不能になったメンバーはコマンド入力をスキップされ、パーティ全員が戦闘不能になったときに
  DEFEATへ遷移する（1人が倒れただけでは終わらない）。
- 回復魔法・リライフは自動的に「HP割合が最も低い生存メンバー」「戦闘不能の先頭メンバー」を
  対象にする（対象選択UIは今回のスコープ外の簡略化）。
- どうぐコマンドは実際の`Inventory`所持数を消費する（以前は常に「つかえる どうぐがない」だった）。

正式な攻略骨格:
- デーマスは中ボス級。
- Lv15程度の進行帯を目安とする。
- デーマスは「ミラー」に関係する攻略構造を持つ。
- 強力な「ダイダイン」で主人公側を追い込む。

原作資料で確認されたデーマスのHP1000 / MP500 / 攻撃300等は「原作側参考値」であり、MQ0最終ゲームバランス値として自動採用しない。

## 9.1 まじん戦（No.07）

- No.07まじんのどうくつの10Fで扱う。主人公一人の特殊ターン制Dungeon RPG内の戦闘であり、通常の`BattleScene`へ遷移するかは既存ローカル実装を優先する。
- 通常に殴るだけでは勝ちにくい、特定の魔法またはアイテムを使わせる攻略型。
- 戦闘中に巨大化する。
- ヒートを有効手段にする案は最有力だが、正式な弱点、アイテムの有無、巨大化条件、数値はTBD。AIは確定しない。

**2026-09-22 実装（TEMP_TEST_VALUE）**: `MajinCaveTurnSystem.castHeat()`でヒートを使えるようにした。
まじんは`regenPercentPerTurn: 0.16`(最大HP割合/敵phase)で自己再生し、通常近接1回分の
相対量をわずかに上回るため、ヒートで`heatSuppressionTurns`分だけ再生を止めない限り
理論上撃破できない（headlessシミュレーションで検証、`tests/bossBalance.test.mjs`）。
「巨大化」演出そのものは未実装（再生ギミックのみ）。想定レベル帯はLv9〜10前後（ユーザー確定）。

**2026-09-23注記**: `MONSTER_SPEC.md` §1.1でまじんのHP/攻撃/防御/素早さ/EXP/G(520/34/28/15/250/100)が
モンスター全体の正本として確定した。ただしこの10F専用Dungeon RPG実装(`MAJIN_CAVE_ENEMIES.majin`、
HP150/攻撃19)は、上記のヒート再生阻害パズルと一体で調整された既存仕様のため、意図的に別の値を
維持している(defense概念自体を持たない別の戦闘モデル)。BattleSystemベースで実装する場合の正本は
`src/data/bosses.ts`の`MAJIN`に用意した。

## 9.2 バトラス戦（No.19）

**2026-09-23確定**: `src/data/bosses.ts`の`BATORASU`はHP2200/攻撃74/防御78/素早さ34/EXP1100/G650
（`MONSTER_SPEC.md` §1.1のユーザー確定値、旧TEMP_TEST_VALUEのHP5200/攻撃68/防御74を置き換えた）。
毒(§14)はタロサの最終弓の武器アクションとして実装し、入手方法は装備の自動更新
(`getDefaultWeaponForLevel`、Lv19以降)。想定レベル帯Lv19〜21前後（ユーザー確定）で、
確定値でも毒なしは複数シードのシミュレーションで安定して敗北、毒ありは安定して勝利することを

## 10. 終盤ボス
- バトラス
- オロチまおう

公開資料では重大ネタバレの名前・姿を伏せる。

### オロチゾンビ
- **裏ボス**として扱う。
- No.20「オロチへの道／オロチのしろ／最終地点」の終章で扱う。公開時の名称は`？？？`とする。
- 1回目は通常のレベル／火力だけで押し切る戦闘として設計しない。
- 1回目 → 異常／フーフー → 偽リセット → 「もういちど」へ接続する。
- 「もういちど」後、わたべ加入／特殊参加を経て再戦する。
- この一連を**裏ワザ**として扱う。
- 再戦ではわたべの「とくだいヒット」等、通常進行では得られない要素を最終解決へ関与させる。
- 異常な強さは、複数のモンクエ世界／バージョンが重なったMQ0世界の裏構造と意味的につなげる。
- 1回目と再戦のHP・攻撃・AI・強制イベント条件・勝敗条件はTBD。

最終特殊戦は通常戦闘だけで完結せず `GLITCH_SPEC.md` / `STORY_FLOW.md` へ接続する。

### オロチまおうとNo.20
- No.20は「オロチへの道 → オロチのしろ → 最終地点」を一つの終章として扱う。
- 終章にはNo.09と差別化した縦シューティング要素を含めるが、オロチまおう戦では通常のコマンドRPGへ戻る。
- 主人公・タロサ・ミレイの装備、魔法、道具、武器アクションを総動員して倒す。
- オロチまおうは「勇者に倒される魔王」という結末を拒絶して限界を越える力へ手を出し、その結果として裏ボスへ至る。
- 縦シューティングの切替地点、オロチまおうの最終AI・数値、裏ボス化の演出条件はTBD。

**2026-09-23確定**: `src/data/bosses.ts`の`OROCHI_MAOU`はHP3200/攻撃118/防御104/素早さ46/EXP3000/G0
（`MONSTER_SPEC.md` §1.1のユーザー確定値、旧TEMP_TEST_VALUEのHP3600/攻撃104/防御64を置き換えた）。
想定レベル帯Lv23前後（ユーザー確定、通常クリア帯）。

**2026-09-23判明**: 確定した防御104(旧64から+63%)により、近接攻撃＋回復のみの簡易headless
シミュレーションでは、Lv23・装備不足は従来どおり安定して敗北するが、Lv23・3人最高クラス装備は
敵HPを3200中520まで削った時点で全滅し、以前のように安定して勝利しなくなった。Lv25(レベルキャップ)
最高装備では際どく勝利する。ダメージ計算式・ボスAIは変更していないため、`tests/bossBalance.test.mjs`の
該当2件は`todo`化して現象を保存し、数値を勝手に書き換えていない。実プレイヤーは防御を無視する
攻撃魔法(ビーター/ビーテスト/ダイダイン)も使えるため詰みとは限らないが、「Lv23前後で勝てる」という
本節の記述との整合はユーザー確認を推奨する(`MONSTER_SPEC.md` §11参照)。
主人公だけ最高装備でも他2人が装備不足なら勝てない設計（3人全員のビルドが必要）は
`BattleSystem`の複数アクター対応で自然に再現される。正式ポートレート・背景画像は未確認のため
`BattleScene`へは未接続。

- 草むら・危険地域等で通常戦闘が発生する。

## 12. 戦闘終了
勝利時:
- EXP
- G
- 必要に応じてドロップ
- レベルアップ判定
- ボス時は進行フラグ

現行実装（2026-09-19、EXPテーブルは2026-09-22更新）:
- イベント戦の勝利時、加入中の全員へ同量のEXP、所持金、敵定義にある低確率ドロップを一度だけ付与する。
- Lv1・EXP0開始と勝利報酬の保存は実装済み。**Lv1〜25累積EXPテーブルはCHARACTER_GROWTH.md §11.2のユーザー確定値**（`src/data/expTable.ts`）。敵ごとのEXP/G/ドロップ確率は引き続き`TEMP_TEST_VALUE`であり、最終バランスではない。
- `?battleTest=`による単体の戦闘表示確認は、ユーザーのローカルセーブへEXP・G・道具を書き込まない。
- 2026-09-24: 勝利でレベルが上がった場合、報酬メッセージの後に次のページを順に送る。①メンバーごとの「○○は　レベルNに　あがった！」（金色フラッシュ・中央に弾んで出る「LEVEL UP!」・該当ステータス窓の金色点滅と立ちのぼる光の粒）→②戦闘の最後に能力増加の説明「○○の　のうりょくが　あがった！」＋さいだいHP／さいだいMP／こうげき／ぼうぎょ／すばやさの増加量（増えた項目のみ、こうげきは武器補正込み）→③新しく覚えた魔法。演出の色・尺はTEMP_TEST_VALUE、効果音はAudio未実装のため無し。

## 12.1 戦闘開始演出

- 通常のフィールド戦闘は、戦闘画面へ切り替わる前に約1.3秒間の共通演出を再生する。
- フィールドを過度に発光させず、画面上のドット片がわずかにねじれながら中心へ吸い込まれる「ピクセル・ボルテックス」を採用する。深い藍・灰青を基調に、ごく少量のくすんだ赤・青緑の断片と短い走査線のずれを混ぜ、MQ0世界の制御された違和感を示す。菱形ゲート、金色の光片、画面フラッシュは使用しない。
- この表現は通常戦闘用の軽い予兆であり、`GLITCH_SPEC.md`の終盤における強い異常演出を先取りしない。
- 演出中は入力をロックする。会話イベント戦と、ビーエのもり（内部`starting_forest`）のランダムエンカウントで同じ演出を使う。
- `?battleTest=`は戦闘画面単体の確認を速く保つため、この開始演出を省略する。

通常敗北時:
- 実セーブを壊さない。
- 進行不能状態を作らない。

オロチゾンビ1回目:
- 通常の敗北／Game Overへそのまま落とさない。
- ストーリー用の異常遷移として「もういちど」シーケンスへ接続する。
- 実セーブ状態・ジャンカード取得状態を保護する。

## 13. 実装禁止
- 未確定数値をAIが最終値として確定する。
- ボス攻略を単なるHP増加だけで難しくする。
- 「クリティカル」表記へ戻す。
- デスタロッサをMQ0の敵として追加する。
- オロチゾンビ1回目を通常のGame Overとして処理して「もういちど」導線を失う。
- わたべ参加前提の再戦を、通常周回／New Game扱いにする。
