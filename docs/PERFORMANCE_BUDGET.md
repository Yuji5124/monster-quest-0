# Monster Quest 0 パフォーマンス基準

更新日: 2026-09-09

## 1. 目的
PCでは動くがiPhone Safariで重い、という状態を後半まで放置しない。

## 2. 基本方針
- iPhone Safariを主要ターゲットとして扱う
- 画質より操作不能回避を優先する
- レトロRPGの見た目を活かし、不要な高負荷演出を避ける
- Vertical Slice段階から実機相当条件を確認する

## 3. フレームレート
- 通常移動 / メニュー / 戦闘で滑らかな操作感を維持する
- 継続的な大幅フレーム落ちを許容しない
- 一時的演出のためにゲーム操作が長時間重くなる構成を避ける

具体的な実測値は実装後に記録し、端末ごとの結果を `QA_SPEC.md` またはテスト記録へ残す。

## 4. アセット
- 同一画像の重複ロードを避ける
- 使用しない巨大画像を常駐させない
- 戦闘背景など大きい画像は必要な解像度を確認する
- 透明余白が極端に大きいPNGを避ける
- 画像を無意味に高解像度化しない

## 5. Scene切替
- 前Sceneの不要オブジェクト / listener / timerを残さない
- BGM二重再生を防ぐ
- Scene往復を繰り返して負荷が増えないか確認する

## 6. Particle / Effect
- 魔法演出は短時間で完結させる
- 大量particleを常時出し続けない
- 画面外effectを不要に更新し続けない

## 7. マップ
- 見えていない大量オブジェクトを無制限に更新しない
- NPCの重いAI処理を毎フレーム大量実行しない
- 約5時間RPGに不要な常時シミュレーションを追加しない

## 8. DOM / Canvas
- Phaser Canvas/WebGLと重いDOM UIを無計画に混在させない
- モバイルブラウザで画面スクロール・拡大が誤発生しないようにする

## 9. メモリ確認
最低限、以下を繰り返す。
- 町 ↔ フィールド
- フィールド ↔ 戦闘
- ダンジョン ↔ 戦闘
- メニュー開閉
- セーブ / ロード

繰り返すほど明確に重くなる場合は完成扱いにしない。

## 10. ロード
- タイトル開始時に全ゲーム素材を無条件で一括ロードする設計を避ける
- ただし複雑な独自ストリーミング基盤は作らない
- シンプルなScene / エリア単位ロードを優先する

## 11. ネットワーク
一度ゲーム本体がロードされた後、通常プレイの基本進行を外部API依存にしない。
AIサービスへの常時接続をゲーム本編要件にしない。

## 12. パフォーマンス問題時の優先順位
1. 進行不能 / 入力遅延を直す
2. 不要処理を削る
3. 重複ロードを直す
4. Effect量を調整
5. 画像サイズを調整
6. 最後に見た目を必要範囲で軽量化

最初から画質を大きく落とすのではなく、原因を特定する。
