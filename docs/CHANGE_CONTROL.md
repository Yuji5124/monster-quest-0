# Monster Quest 0 仕様変更管理

更新日: 2026-09-09

## 1. 目的
過去仕様、会話中の案、実装上の仮決定、現在の正式仕様が混ざることを防ぐ。

## 2. Source of Truth
矛盾時の優先順位：
1. `DECISIONS.md`
2. 各専門仕様書
3. `PROJECT_OVERVIEW.md`
4. `CONTENT_MATRIX.md` の状態
5. 実装コード
6. 古いコメント / 過去案

コードに書いてあるから正式仕様、とは限らない。

## 3. 変更レベル
### Level A: 実装調整
ゲーム設定を変えない技術変更。
例：
- バグ修正
- 処理最適化
- UIのSafe Area修正

AI判断で実施可能。

### Level B: バランス調整
例：
- エンカウント率
- 演出待ち時間
- UI余白

既存仕様範囲内なら調整可能。ただし確定値として残す場合は専門仕様へ反映する。

### Level C: ゲーム仕様変更
例：
- キャラクター設定
- モンスター総数
- カード総数
- ストーリー順
- ボス攻略法
- 魔法効果
- 主要マップ追加 / 削除

AIが独断で確定しない。人間の決定を優先し `DECISIONS.md` へ反映する。

## 4. 未確定
未確定事項は `TBD` / `null` / `未確定` と明示する。
空欄をAIが自動で埋めて正式化しない。

## 5. 廃止仕様
古い仕様を残す必要がある場合は、現行仕様と混同しないよう `DEPRECATED` と明記する。

例：
- 旧プレイ時間 約1時間 → DEPRECATED
- RPGJS候補 → DEPRECATED
- ジャンカード20枚 → DEPRECATED
- ASRS利用 → DEPRECATED

## 6. 公開リポジトリ
公開GitHubには、重大な終盤ネタバレ・最終回答・隠しボスの真名 / 姿などを保存しない。
実装に必要な秘密情報は公開仕様書とは別管理を前提とする。

## 7. 変更時の作業
仕様変更が確定したら：
1. `DECISIONS.md` を確認 / 更新
2. 専門仕様書を更新
3. 必要なら `CONTENT_MATRIX.md` 更新
4. コード / data更新
5. QA

## 8. 数字の変更
カード枚数、敵数、料金、プレイ時間などの数字は特に古い値が残りやすい。
変更時はGitHub全体を検索して古い値が残っていないか確認する。

## 9. 名前の変更
キャラクター、魔法、地域、アイテム名を変更した場合：
- 表示名
- ID
- asset path
- data参照
- セーブ互換
への影響を確認する。

安定IDまで毎回変更しない。
