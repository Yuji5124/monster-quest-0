# モンスタークエスト0 特殊ゲームプレイ仕様

最終更新: 2026-09-20 JST

このファイルは、通常のレトロRPG進行から一時的に見た目・操作・ゲームルールが変化する**特殊区間**の正本である。
地域番号と物語上の接続は `MAP_FLOW_SPEC.md`、通常ローカルマップ方式は `MAP_SYSTEM.md` を正とする。

## 1. 基本コンセプト
Monster Quest 0は基本的には昔ながらのコマンドRPGとして成立させる。
その上で、世界の混線・破損・別バージョンの断片が表面化する地点では、**ゲームジャンルそのものが一時的に変化してよい**。

特殊区間は単発の unrelated mini-game として置かない。
「この世界には異なるゲーム／世界の断片が混ざっている」という物語上の異常を、プレイヤーが操作感そのもので体験するために使う。

原則:
- 通常RPG部分が作品の基盤。
- 特殊区間は短く濃くし、1区間が長すぎて別ゲーム化しない。
- 特殊区間にも本編上の目的、報酬、人物、ボス、進行上の意味を持たせる。
- 実データ破損、意図しないフリーズ、進行不能は使わない。
- 既存作品の画面・ルール・アートを直接コピーせず、MQ0独自表現へ置き換える。
- 特殊区間の正確な配置、尺、操作、難易度は個別にTBD管理する。

## 2. 正式採用済みの特殊要素

### 2.1 ビーエのむら：通常景観とバグ景観の混在
- No.03「ビーエのむら」は異常地域として扱う。
- 普通に見える景観と、壊れた／荒れた／データ化けしたような景観がちらつく・部分的に混在する。
- 背景だけでなく、必要に応じてNPC、BGM、UIの一部も短時間だけ劣化させてよい。
- 常時読みにくくせず、通常状態との落差で異常を感じさせる。
- 「画像が荒い町」というアイデアを、この系統の表現として正式に採用する。適用をビーエだけに限定するか、別の1地点にも使うかはTBD。

### 2.2 ザボンのむら：壊れた景観
- No.06「ザボンのむら」は、地形や建物が壊れた／崩れた印象を持つ村として扱う。
- 単なる廃墟ではなく、「世界の一部がうまく構成されていない」ような違和感を含めてよい。
- タロサに関係する地域性と両立させる。

### 2.3 まじんのどうくつ：ターン制ダンジョンRPG化
- No.08「まじんのどうくつ」に入ると、通常RPGの移動方式から**ターン制ダンジョンRPG方式**へ切り替わる。
- プレイヤーが1歩／1行動すると敵側も1行動する。
- 部屋、通路、宝箱、敵配置等は入るたびに変化してよい。
- 全3〜8F程度の小規模構成を目安にし、正確な階数はバランス確認後に確定する。
- 通常RPG側のレベル・HP・装備・アイテム等をどこまで引き継ぐかはTBD。
- 最奥では通常のボス戦へ戻り「まじん」と戦う。

### 2.4 まじん戦：戦闘中に巨大化
- まじんは戦闘中、ターン経過またはHP減少に応じて段階的に巨大化する演出を正式採用する。
- 単なる拡大アニメではなく、戦闘が進むほど画面を圧迫し、通常の戦闘枠からはみ出す迫力を出す。
- 巨大化に能力変化を連動させるかはTBD。
- ヒート等の攻略要素と巨大化演出が矛盾しないように設計する。

### 2.5 ブロック／ボクセル化する城
- 城の内部へ入った瞬間、通常の2D／高解像度背景とは異なる**ブロック／ボクセル風の立体世界**へ切り替わる特殊区間を正式採用する。
- 既存ゲームの画面を模倣せず、MQ0独自の簡素なブロック空間として制作する。
- 3D表現、擬似3D表現、2.5D表現のどれを採用するかは実装コストを見て決める。
- どの城に適用するかはTBD。候補はレインランドじょう、ポサロ城、オロチのしろ等だが、AIが独断で確定しない。
- 「世界の断片が別の描画方式へ切り替わっている」ことをプレイヤーに体験させる。

### 2.6 ぬまちのどうくつ：アクション化
- No.17「ぬまちのどうくつ」は、多数の小型モンスターをリアルタイム操作で倒して進む特殊ダンジョンとする。
- No.08のターン制ダンジョンRPGとは明確に異なる操作感を持たせる。
- 敵数を多く見せつつ、1体ずつは軽量な処理・短い撃破時間にする。
- HP、武器、魔法、経験値を通常RPG側とどこまで共有するかはTBD。

### 2.7 後半シューティング区間
- **後半にシューティングゲーム方式へ切り替わる区間を正式採用する。**
- 単なるボーナスステージではなく、世界混線が強くなった結果として別ルールの空間へ入る構造にする。
- 縦スクロール／横スクロール／固定画面のどれにするかはTBD。
- 操作キャラクター、攻撃方法、敵、ボス、ステージ位置、所要時間はTBD。
- 本編のレベル・装備・魔法・仲間の能力をシューティング側へどう反映するかもTBD。
- 長時間の本格STGにせず、後半のテンポを変える短く濃い区間とする。
- 終了後は通常RPGへ自然に戻り、ストーリー進行を継続する。

### 2.8 横アクション区間
- **横アクション方式へ切り替わる区間を正式採用する。**
- 横スクロール／固定画面連結などの具体方式はTBD。
- ジャンプ、攻撃、回避、段差、落下、敵配置などの採否はTBD。
- 操作キャラクター、配置マップ、ボス、所要時間、通常RPG側ステータスとの連携はTBD。
- 単なる寄り道ミニゲームではなく、世界混線によって「横方向のアクションゲームのルール」が侵入した区間として扱う。

### 2.9 縦アクション区間
- **縦アクション方式へ切り替わる区間を正式採用する。**
- 上下方向へ進行するアクション、トップダウン型、縦スクロール型など、具体方式はTBD。
- 攻撃、回避、障害物、敵配置、スクロール方式の採否はTBD。
- 操作キャラクター、配置マップ、ボス、所要時間、通常RPG側ステータスとの連携はTBD。
- シューティング区間とは別枠のアクション区間として扱い、操作感を重複させない。

## 3. 特殊区間の配置方針
特殊要素を序盤から連発しない。

目安:
- 冒頭: 約5秒の異常のみ
- 序盤: ビーエ等で「見た目がおかしい」程度
- 中盤: まじんのどうくつで初めてゲームルール自体が大きく変わる
- 中盤〜後半: ブロック／ボクセル城など、描画方式の異常を拡大
- 後半: ぬまちのどうくつのアクション、横アクション、縦アクション、シューティング等、操作方式の混線を強める
- 最終盤: バグ／偽リセット／「もういちど」へ収束

ゲームが進むほど「見た目の異常 → ルールの異常 → 世界そのものの異常」へ段階的に強くする。

## 4. 通常RPGとの接続
特殊区間に入る前後で、次の情報を安全に保持する。
- パーティ
- HP / MP
- レベル / EXP
- 装備
- 所持品
- 所持金
- 魔法
- 進行フラグ
- ジャンカード取得状態

特殊区間専用の一時ステータスを追加してもよいが、終了時の変換ルールを明示する。
「特殊区間に入ったため通常データが失われる」という実破損は行わない。

## 5. 実装方式
通常ローカルマップの `BACKGROUND / COLLISION / EVENT / OBJECT` をすべての特殊区間へ強制しない。

専用Scene／専用Runtimeを許可する例:
- DungeonRogueScene
- ActionDungeonScene
- HorizontalActionScene
- VerticalActionScene
- ShooterScene
- VoxelCastleScene / BlockCastleScene

名称は例であり、実装時に確定する。
重要なのは、入口・出口・セーブ状態・イベントフラグを通常RPG側と共通契約で接続すること。

## 6. やらないこと
- 特殊要素を説明なくランダムに並べる。
- 本編と無関係なミニゲーム集にする。
- すべてのマップを特殊化して通常RPGの基盤を失う。
- 別作品の固有UI・固有キャラ・固有マップをコピーする。
- 難しすぎる特殊区間を本編進行の壁にする。
- 特殊区間のために目標プレイ時間を大幅超過させる。
