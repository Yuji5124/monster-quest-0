# Monster Quest 0 Phaser実装アーキテクチャ

更新日: 2026-09-09

## 1. 目的
Claude Code / Codex / Phaser Game Agentが、同じ責務分離で実装するための基準。

## 2. Scene責務
### BootScene
- 最低限の初期化
- 共通設定読み込み
- 必須アセット読み込み
- エラー時に原因を把握できる状態にする

### TitleScene
- タイトル表示
- はじめから
- つづきから
- 必要なら設定

ゲームロジックを持たせない。

### WorldScene
- フィールド / 町 / 村 / ダンジョン移動
- プレイヤー移動
- NPC / オブジェクト表示
- 衝突
- イベント起動
- ランダムエンカウント要求

戦闘処理そのものは持たせない。

### BattleScene
- 戦闘UI
- コマンド入力
- ターン進行
- 敵AI呼び出し
- 勝敗
- 戦闘結果

個別モンスター名による分岐を大量に直書きしない。

### MenuScene
- ステータス
- アイテム
- 魔法
- 装備
- ジャンカード閲覧
- 設定

### GameOverScene
- 全滅時処理
- 再開導線

## 3. System責務
### EventSystem
会話、宝箱、スイッチ、フラグ、ワープ、戦闘開始等を統一的に処理する。
詳細は `EVENT_SYSTEM_SPEC.md`。

### EncounterSystem
- エリア別出現テーブル
- エンカウント判定
- 戦闘編成決定

### BattleSystem
- ダメージ計算
- ターン順
- 状態管理
- 戦闘不能
- 経験値
- レベルアップ

### SaveSystem
- セーブ / ロード
- version管理
- migration
- 壊れたデータへの安全なフォールバック

### AudioSystem
- BGM遷移
- SE
- ミュート / 音量
- Scene切替時の二重再生防止

### InputSystem
- キーボード
- タッチ
- iPhone Safari
- 必要に応じたゲームパッド

## 4. データ駆動
以下は原則としてコードに直書きしない。
- モンスター基本値
- アイテム基本値
- 魔法基本値
- NPC会話
- エンカウントテーブル
- 宝箱中身
- マップ接続
- ジャンカード一覧

## 5. 状態管理
最低限、以下の概念を分離する。
- GameData: 固定定義
- GameState: プレイ中に変化する状態
- SceneState: 画面内だけの一時状態

固定データを直接書き換えない。

## 6. イベントフラグ
イベント進行に必要なフラグは一元管理する。
例：
- `story.*`
- `party.*`
- `boss.*`
- `chest.*`
- `npc.*`

文字列の意味が曖昧な `flag1`, `tmp2` のような名前は禁止。

## 7. マップ
- マップごとに独自コードを増やしすぎない
- 衝突 / イベント / 出入口 /前景などのレイヤー責務を統一する
- 使用するレイヤー名は `NAMING_CONVENTIONS.md` に従う
- 実タイルサイズは正式素材を確認して決定し、未確認値をハードコードしない

## 8. アセット読み込み
- ファイルパスを可能な範囲で集約する
- 同一画像を別名で重複ロードしない
- 存在しない素材は黙って別素材へ置換しない
- 正式素材が見つからない場合は不足として報告する

## 9. モバイル
- タッチ操作をキーボード版完成後の後付けにしない
- Safe Area対応
- hover必須操作禁止
- 画面リサイズに耐えるUI

## 10. 禁止パターン
- 1つのSceneが全機能を持つ
- 町・村ごとのコピペBattleSystem
- 特定ボスのために共通戦闘を壊す
- セーブデータへPhaserオブジェクトそのものを保存
- イベントの進行条件を画面表示だけに依存させる
- 実際のバグ / フリーズを演出として使う

## 11. 判断原則
迷った場合は、最も高度な設計ではなく「約5時間のMonster Quest 0を短期間で完成できる、単純で再利用可能な設計」を選ぶ。
