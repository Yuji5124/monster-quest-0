# モンスタークエスト0 ゲーム仕様

最終更新: 2026-09-11 08:31 JST

## 1. 基本コンセプト
- タイトル: **モンスタークエスト0**
- 正式サブタイトル: **～幻の冒険の書～**
- 広告・紹介用コピー: **「誰も知らないゲーム、やってみる？」**
- ジャンル: 昔懐かしいレトロRPG風のコマンドRPG
- 想定プレイ時間: **初見クリア約4時間30分 / 寄り道込み約5時間30分を目標**
- フィールド・歩行キャラクター: FC〜初期SFCを感じる2Dドット絵
- 戦闘・イベント背景: 高品質な2D JRPG／アニメ背景方向
- UI: ファミコン風のシンプルで読みやすいデザイン
- 対象: 子どもだけでなく、大人と子どもが一緒に遊べる構成
- 既存ゲームの直接模倣ではなく、完全オリジナルとして成立させる
- 全編を同じ密度で豪華化せず、**始まり・主要人物の交差・終盤／EDを重点的に濃く作る**

## 3. オープニング
- タイトル → 「はじめから」 → **約5秒の短い制御されたバグ／異常画面** → 「はじまりのばしょ」で主人公が焚き火のそばで目覚める。
- 「はじまりのばしょ」はイベント専用マップで、夜版／昼版を用意する。
- 最初の目覚めは夜版。
- 風景・音・焚き火・短い台詞・小さな操作で、主人公と一緒にこの世界へ入っていく感覚を作る。
- 長いムービーや長文説明にはしない。
- 開始直後の偽「ぼうけんのしょが きえました」は使わない。
- 本格的な世界崩壊・バグ演出は終盤へ残す。
- プレイヤーへ直接語りかけるメタ会話は行わない。

詳細: `docs/OPENING_SPEC.md`

## 4. 主要パーティ
主要パーティは3人。

### 主人公
- **男性**。
- 本来は別のモンスタークエスト作品／別バージョン世界にいた、特別な勇者ではない**ただのNPCだった人物**。
- 世界間の異常によってMonster Quest 0へ迷い込む。
- 序盤ではこの出自を直接説明しない。
- 主人公自身も状況を完全には理解していない状態から始まる。
- 何者でもなかった人物が、この世界で物語の中心へ変わっていく構造を重視する。
- 固有魔法「エレキテル」は採用済み能力として維持する。
- 最終的な外見・歩行スプライトは、旧女性勇者風デザインではなく最新男性主人公設定に合わせて更新する。

### タロサ
- 物語途中で加入
- 青い逆立った髪
- 尖った耳
- 弓を使用
- 緑の腰布
- 強さを求める展開を持つ
- ザボンのむらに関係する

### ミレイ
- 物語途中で加入
- レインランドの姫
- 自分が姫であることを隠して旅に加わる

### わたべ
- 主要3人パーティとは分ける
- イベント／特殊参加キャラクターとして管理する
- 固有攻撃「とくだいヒット」を使用できる
- 終盤の解決に関わる重要人物

詳細: `docs/CHARACTER_GROWTH.md`

## 5. 世界・地域設計
- 国: レインランド
- **全体ワールドマップ、主要地域配置、大枠の進行は変更しない**
- Monster Quest 0の世界には、異なるモンスタークエスト作品／バージョン由来の断片が混在しているという裏構造を持たせる
- 異なる世界のボス・モンスター・要素が同居していることは、終盤の異常や強すぎる存在の背景説明につながる
- ただしこの裏構造を序盤から直接説明しない
- 各町・村には生活・文化・産業・周辺地域との関係を持たせる
- ダンジョンは単なる通路ではなく、その地域に存在する理由・生態・歴史を持たせる
- 全域の基本移動は徒歩
- 船／飛行によるワールド移動は基本システムにしない
- 橋は旧案より数を減らし、過密にならないよう整理する
- **町・村・城の内部マップは旧案より小さくする**
- **ダンジョン内部も旧案より小さくする**
- 縮小は一律50%固定ではなく、地域ごとの役割・探索密度・滞在時間に合わせて調整する
- NPC人数はコンパクト化した各地域に合わせて再編集する
- 最終的な規模は「初見約4時間30分 / 寄り道込み約5時間30分」のテンポを基準に決める

## 6. NPC・会話
- NPC会話は物語順に町・村ごとに整理する
- 村人・町人には基本2パターン程度の短い台詞を用意する
- 攻略ヒントだけでなく、生活感、仕事、地域情報、人物関係、噂、事件の気配を入れる
- 全員を攻略ヒント役にしない
- 全員を主要人物の説明役にしない
- タロサ関連地域でも全員がタロサのことを話す構成にしない
- 主要人物に興味がない普通の住民も入れる
- 重要な答えを1人のNPCが全部説明せず、複数の断片情報から気づける設計を優先する
- これまで作成した会話案は素材として保持し、**縮小後の町・村・城に必要なNPCだけを選抜・統合する**

詳細: `docs/NPC_SPEC.md`

- わたべのみ固有の**「とくだいヒット」**を使用できる
- 主要ボスは単純なレベル勝負だけでなく、少ないヒントから攻略法を見つける遊びを重視する

## 15. セーブ・進行フラグ
- GameStateを一元管理する
- ストーリー、パーティ、ボス、宝箱、カード、設定を保存する
- 実データ破損を演出に利用しない
- 開始直後の偽セーブ消失は現行仕様では使わない

詳細: `docs/SAVE_FLAG_SPEC.md`

## 16. 異常・バグ演出
- **導入では約5秒の短い制御された異常演出を使用する**
- これは世界の真相を説明する本格バグではなく、後から意味が分かる最初の違和感として扱う
- 序盤〜中盤の本編は普通のRPGとして成立させる
- 世界の本格的な崩壊は終盤に入ってから段階的に強める
- 実エラーではなく制御された演出
- 最終戦で画面バグ → フーフーを連想する演出 → OP / タイトルへ戻るように見せる → 「もういちど」へつなげる
- 通常の強さだけでは解決できない本当の終盤へ続く

詳細: `docs/GLITCH_SPEC.md` / `docs/STORY_FLOW.md`

## 17. UI・入力
- キーボードとタッチを共通actionへ変換する
- iPhone Safariを後付け対応にしない
- 会話／メニュー／戦闘等でinput lockを管理する
- タッチ領域は小さすぎないようにする

詳細: `docs/UI_INPUT_SPEC.md`

## 18. 開発方針
- GitHubを仕様・ソース・アセット管理の中心にする
- 実装中心: **Phaser 3 / Phaser Game Agent**
- Claude Code: メイン実装
- Codex: レビュー / デバッグ / QA
- Astra: コア安定後に必要に応じて使用
- ASRSは使用しない
- マップ制作はTiled等との連携を想定
- Webブラウザで遊べる構成を優先
- iPhoneではHTTPS公開環境で実機確認する
- 目安: **80% AI制作 + 20% 人間の視覚・テンポ調整**

## 19. 制作フロー
1. GitHubのMDに仕様・名称・禁止事項を書く
2. AIが仕様を読める状態にする
3. **始まりの重点区間を先に具体化する**
4. Vertical Sliceを実装
5. iPhone Safariまで早期確認
6. Vertical Sliceが製品品質に近づいてから本編地域を量産
7. 人間が視覚・テンポを調整
8. 全体を**初見約4時間30分 / 寄り道込み約5時間30分**へ調整

## 20. 現在の制作優先度
1. GitHub仕様の一貫性確保

5. **NPC人数・配置をコンパクト化した町に合わせて再編集**
6. **ダンジョン内部サイズ・階層・分岐を縮小設計**
