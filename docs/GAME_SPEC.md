# モンスタークエスト0 ゲーム仕様

最終更新: 2026-09-10 13:50 JST

## 1. 基本コンセプト
- タイトル: **モンスタークエスト0**
- 正式サブタイトル: **～幻の冒険の書～**
- 広告・紹介用コピー: **「誰も知らないゲーム、やってみる？」**
- ジャンル: 昔懐かしいレトロRPG風のコマンドRPG
- 想定プレイ時間: **約5時間を目標**
- フィールド・歩行キャラクター: FC〜初期SFCを感じる2Dドット絵
- 戦闘・イベント背景: 高品質な2D JRPG／アニメ背景方向
- UI: ファミコン風のシンプルで読みやすいデザイン
- 対象: 子どもだけでなく、大人と子どもが一緒に遊べる構成
- 既存ゲームの直接模倣ではなく、完全オリジナルとして成立させる

## 2. タイトル画面
基本メニュー:
- はじめから
- つづきから
- ジャンカードガチャ
- ジャンカード図鑑
- たびのあいことば
- 設定

旧名称「ふっかつのじゅもん」は使わず、**「たびのあいことば」**に統一する。

## 3. 主要パーティ
主要パーティは3人。

### 主人公
- 女性勇者風
- 金髪
- 青いヘッドバンド
- 額に赤い宝石
- 赤いマフラー
- 金色系装備
- 剣を使用
- 固有魔法として「エレキテル」を覚える

### タロサ
- 物語途中で加入
- 青い逆立った髪
- 尖った耳
- 弓を使用
- 緑の腰布
- 強さを求める展開を持つ
- ザボンのむらに関係する

### ミレイ
- 物語途中で加入
- レインランドの姫
- 自分が姫であることを隠して旅に加わる

### わたべ
- 主要3人パーティとは分ける
- イベント／特殊参加キャラクターとして管理する
- 固有攻撃「とくだいヒット」を使用できる

## 4. 世界・地域設計
- 国: レインランド
- 各町・村には生活・文化・産業・周辺地域との関係を持たせる
- ダンジョンは単なる通路ではなく、その地域に存在する理由・生態・歴史を持たせる
- 全域の基本移動は徒歩
- 船／飛行によるワールド移動は基本システムにしない
- 橋は旧案より数を減らし、過密にならないよう整理する

主要地域・地点として以下を扱う:

## 5. NPC・会話
- NPC会話は**はじまりのまちからストーリー順に、町・村ごとに整理して膨らませる**
- 村人・町人には基本2パターン程度の台詞を用意する
- 攻略ヒントだけでなく、生活感、仕事、地域情報、人物関係、噂、事件の気配を入れる
- 採用済みのアイテム・魔法・設定だけを会話へ出す
- 重要な答えを1人のNPCが全部説明せず、複数の断片情報から気づける設計を優先する
- 詳細は `docs/NPC_SPEC.md` を正本とする

## 7. 戦闘
- 通常攻撃、魔法、アイテム等のコマンド式
- 旧「クリティカル」表現は使わず、戦闘メッセージを**「だいヒット」**へ統一する
- わたべのみ固有の**「とくだいヒット」**を使用できる
- 主要ボスは単純なレベル勝負だけでなく、少ないヒントから攻略法を見つける遊びを重視する

### デーマス
- 中ボス
- Lv15程度を目安
- 「ミラー」を使用する設定を持つ
- デーマス側の強力な「ダイダイン」に対し、反射を利用して逆転する攻略構造を採用する

### 終盤
- バトラス
- オロチまおう
- 最終地点の特殊戦

公開資料では終盤ボスの姿・名前を可能な限り伏せる。

## 10. モンスター
- 正式総数: **25体**
- 序盤: プリンキング等

- ボス: バクラー

- デスタロッサは別作品側の設定として扱い、Monster Quest 0には登場させない
- 公開用進捗表では最終ネタバレ対象を `？？？` と表記できる

## 11. ジャンカード
- 正式総数: **45枚**
- 1回20円
- 固定順排出
- ランダム／ダブりなし
- 独立したサブゲームとして成立させる
- 本編攻略必須にはしない
- 45枚コンプリートはやり込み要素
- 詳細は `docs/CARD_SPEC.md`

## 12. 画像・アート方針
- 正式ファイル名・状態: `docs/ASSET_INDEX.md`
- 画像制作仕様: `docs/IMAGE_SPEC.md`
- 機械可読アセット一覧: `assets/asset_catalog.json`
- フィールド・歩行スプライトはドット絵
- 戦闘背景は高品質2D背景へ方針転換済み
- UIはレトロでシンプルなまま維持
- 背景だけを豪華にして、敵・文字・UIを読みにくくしない

## 13. 終盤バグ演出
- 世界は終盤に向けて壊れ始める
- 実エラーではなく制御された演出
- 最終戦で画面バグ → フーフーを連想する演出 → OPへ戻る → 「もういちど」へつなげる
- 起動時の偽「ぼうけんのしょが きえました」演出も、実データを消さずに行う
- 詳細は `docs/GLITCH_SPEC.md`

## 14. 開発方針
- GitHubを仕様・ソース・アセット管理の中心にする
- 実装中心: **Phaser 3**
- **Phaser Game Agentを基本実装担当として使用する**
- ASRSは使用しない
- マップ制作はTiled等との連携を想定
- Webブラウザで遊べる構成を優先
- iPhoneではHTTPS公開（GitHub Pages等）で実機確認する
- 目安: **80% AI制作 + 20% 人間の視覚調整**

### AI担当
- ChatGPT: 仕様整理、画像制作、命名、企画整合
- Phaser Game Agent: Phaser実装の基本担当
- Codex / Claude Code: 複数ファイル修正、デバッグ、参照パス更新、検証

## 15. 制作フロー
1. GitHubのMDに仕様・名称・禁止事項を十分に書く
2. AIが仕様を読める状態にする
3. ローカルへクローン
4. Phaser Game Agentを中心に実装
5. Codex / Claude Codeで複数ファイル修正・検証
6. 人間が20%程度の視覚調整・ゲームテンポ調整を行う
7. iPhoneを含む実機確認
