# モンスタークエスト0 ゲーム仕様

最終更新: 2026-09-11 JST

## 1. 基本コンセプト
- タイトル: **モンスタークエスト0**
- 正式サブタイトル: **～幻の冒険の書～**
- 広告・紹介用コピー: **「誰も知らないゲーム、やってみる？」**
- ジャンル: 昔懐かしいレトロRPG風のコマンドRPG
- 想定プレイ時間: **初見クリア約4時間30分 / 寄り道込み約5時間30分を目標**
- フィールド・歩行キャラクター: FC〜初期SFCを感じる2Dドット絵
- 戦闘・イベント背景: 高品質な2D JRPG／アニメ背景方向
- UI: ファミコン風のシンプルで読みやすいデザイン
- 対象: 子どもだけでなく、大人と子どもが一緒に遊べる構成
- 既存ゲームの直接模倣ではなく、完全オリジナルとして成立させる
- 全編を同じ密度で豪華化せず、始まり・主要人物の交差・終盤／EDを重点的に作る

## 2. タイトル画面
基本メニュー:

旧名称「ふっかつのじゅもん」は使わず、**「たびのあいことば」**に統一する。

## 3. オープニング
- タイトル → 「はじめから」 → 短い導入 → はじまりのまちで操作開始を基本とする。
- 物語の始まりは重点的に丁寧に作る。
- ただし長いムービーにはしない。
- **開始直後のリセット演出・偽セーブ消失演出は使わない。**
- 本格的な異常演出は後半へ回す。

詳細: `docs/OPENING_SPEC.md`

## 4. 主要パーティ
主要パーティは3人。

### 主人公

### タロサ
- 物語途中で加入

- 尖った耳
- 弓を使用
- 緑の腰布

- ザボンのむらに関係する

### ミレイ
- 物語途中で加入
- レインランドの姫
- 自分が姫であることを隠して旅に加わる

### わたべ
- 主要3人パーティとは分ける
- イベント／特殊参加キャラクターとして管理する
- 固有攻撃「とくだいヒット」を使用できる
- 終盤の解決に関わる重要人物

詳細: `docs/CHARACTER_GROWTH.md`

## 5. 世界・地域設計
- 国: レインランド
- 各町・村には生活・文化・産業・周辺地域との関係を持たせる
- ダンジョンは単なる通路ではなく、その地域に存在する理由・生態・歴史を持たせる
- 全域の基本移動は徒歩
- 船／飛行によるワールド移動は基本システムにしない
- 橋は旧案より数を減らし、過密にならないよう整理する
- **町・村・ダンジョンの具体的なマップ規模、建物数、フロア数、NPC人数は再検討中**
- 旧「全体を約半分へ圧縮」案は検討履歴として残すが、現時点では確定値として扱わない
- 最終的な規模は「初見約4時間30分 / 寄り道込み約5時間30分」のテンポを基準に決める

## 6. NPC・会話
- NPC会話は物語順に町・村ごとに整理する
- 村人・町人には基本2パターン程度の短い台詞を用意する
- 攻略ヒントだけでなく、生活感、仕事、地域情報、人物関係、噂、事件の気配を入れる
- 全員を攻略ヒント役にしない
- 全員を主要人物の説明役にしない
- タロサ関連地域でも全員がタロサのことを話す構成にしない
- 主要人物に興味がない普通の住民も入れる
- 重要な答えを1人のNPCが全部説明せず、複数の断片情報から気づける設計を優先する
- これまで作成した大人数／縮小版の会話案は素材として保持し、**地域ごとの最終NPC数と構成はマップ再設計と合わせて再検討する**

詳細: `docs/NPC_SPEC.md`

## 8. 戦闘
- 通常攻撃、魔法、アイテム等のコマンド式
- 旧「クリティカル」表現は使わず、戦闘メッセージを**「だいヒット」**へ統一する
- わたべのみ固有の**「とくだいヒット」**を使用できる
- 主要ボスは単純なレベル勝負だけでなく、少ないヒントから攻略法を見つける遊びを重視する

### デーマス
- 中ボス
- Lv15程度を目安
- 「ミラー」と「ダイダイン」の反射を利用して逆転する攻略構造

### 終盤

- オロチまおう

公開資料では終盤ボスの姿・名前を可能な限り伏せる。

- ダブりなし

## 13. 画像・アート方針
- 正式ファイル名・状態: `docs/ASSET_INDEX.md`

- 機械可読アセット一覧: `assets/asset_catalog.json`

## 14. 音楽・SE
- BGMは01〜08構成
- A案 / B案は最終採用まで候補として保持する
- BGM / SEはAudioSystemで一元管理する
- iPhone Safariの自動再生制約を考慮する

詳細: `docs/AUDIO_SPEC.md`

## 15. セーブ・進行フラグ
- GameStateを一元管理する
- ストーリー、パーティ、ボス、宝箱、カード、設定を保存する
- 実データ破損を演出に利用しない
- 開始直後の偽セーブ消失は現行仕様では使わない

詳細: `docs/SAVE_FLAG_SPEC.md`

## 16. 終盤バグ演出
- 序盤〜中盤は普通のRPGとして成立させる
- 世界は終盤に入ってから段階的に壊れ始める
- 実エラーではなく制御された演出
- 最終戦で画面バグ → フーフーを連想する演出 → OP / タイトルへ戻るように見せる → 「もういちど」へつなげる
- 通常の強さだけでは解決できない本当の終盤へ続く

詳細: `docs/GLITCH_SPEC.md` / `docs/STORY_FLOW.md`

## 17. UI・入力
- キーボードとタッチを共通actionへ変換する
- iPhone Safariを後付け対応にしない
- 会話／メニュー／戦闘等でinput lockを管理する
- タッチ領域は小さすぎないようにする

詳細: `docs/UI_INPUT_SPEC.md`

## 18. 開発方針
- GitHubを仕様・ソース・アセット管理の中心にする
- 実装中心: **Phaser 3 / Phaser Game Agent**
- Claude Code: メイン実装
- Codex: レビュー / デバッグ / QA
- Astra: コア安定後に必要に応じて使用
- ASRSは使用しない
- マップ制作はTiled等との連携を想定
- Webブラウザで遊べる構成を優先
- iPhoneではHTTPS公開環境で実機確認する
- 目安: **80% AI制作 + 20% 人間の視覚・テンポ調整**

## 19. 制作フロー
1. GitHubのMDに仕様・名称・禁止事項を書く
2. AIが仕様を読める状態にする
3. Vertical Sliceを実装
4. iPhone Safariまで早期確認
5. Vertical Sliceが製品品質に近づいてから本編地域を量産
6. 人間が視覚・テンポを調整
7. 全体を**初見約4時間30分 / 寄り道込み約5時間30分**へ調整
