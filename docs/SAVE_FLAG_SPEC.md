# モンスタークエスト0 セーブ・進行フラグ仕様

最終更新: 2026-09-11 JST

このファイルはセーブデータとストーリー進行フラグの責務を整理する正本。JSONの基本構造は `DATA_CONTRACTS.md` に従う。

## 1. 原則
- 実セーブデータを演出目的で削除・破損させない。
- 表示上のバグ演出と保存処理を完全に分離する。
- セーブ形式には `version` を持たせる。
- 後から項目を追加しても旧セーブを可能な範囲で読み込めるよう migration を用意する。
- Sceneごとに独自のLocalStorageキーを乱立させない。
- 終盤の「データが消えた／初めからになったように見える」演出は**表示上の偽リセット**であり、実セーブ状態を失わせない。
- 「もういちど」はNew Gameではなく、同一冒険の最終章進行として管理する。

## 2. セーブ領域
最低限:
```json
{
  "version": 1,
  "player": {},
  "party": [],
  "inventory": {},
  "equipment": {},
  "flags": {},
  "cards": {},
  "map": {},
  "settings": {}
}
```

## 3. 保存対象
### プレイヤー / パーティ
- 現在HP / MP
- レベル
- EXP
- 習得魔法
- 装備
- 加入状態
- 「もういちど」前後で必要なパーティ継続状態

### 所持品
- 所持金
- 通常アイテム
- 重要アイテム
- 装備品

### マップ
- 現在地
- 向き
- 必要な復帰地点
- 開封済み宝箱
- 一度きりイベント状態
- No.18「はじまりのばしょ」の初回／最終章用イベント状態

### ジャンカード
- 取得済みカード
- 取得枚数
- 次回排出番号
- 固定順排出状態

### 設定
- BGM音量
- SE音量
- 必要な操作設定

## 4. フラグ命名
推奨形式:
- `story.*` — 本編進行
- `party.*` — 加入 / 離脱
- `boss.*` — ボス撃破 / 戦闘段階
- `event.*` — 一度きりイベント
- `chest.*` — 宝箱
- `world.*` — 世界状態
- `glitch.*` — 終盤演出
- `tutorial.*` — 初回説明
- `ending.*` — 最終解決／帰還状態

例:
- `story.left_start_town_once`
- `party.mirei_joined`
- `party.tarosa_joined`
- `boss.demas_defeated`
- `glitch.phase_1_started`

例は命名契約。未確定の発生タイミングまで自動確定するものではない。

正式なストーリー順確定後、最低限以下を管理する。
- はじまりのまち出発
- ビーエ地域事件開始 / 解決
- レインランド到達
- ミレイ加入
- タロサ加入
- 勇者装備取得状況
- デーマスの塔解放
- デーマス撃破
- 終盤突入
- バトラス撃破
- オロチまおう関連進行
- オロチゾンビ1回目到達 / 結果
- 最終異常フェーズ
- 偽リセット演出開始 / 完了
- 「もういちど」解放
- 「もういちど」開始
- No.18最終章状態
- 主人公・タロサ・ミレイの記憶継承状態
- わたべ特殊参加
- オロチゾンビ再戦 / 最終解決
- 元世界への帰還
- エンディング到達

## 6. 勇者装備フラグ
- `item.hero_sword_obtained`
- `item.hero_crown_obtained`
- `item.hero_shield_obtained`

塔の条件判定は個別Sceneへ直書きせず、進行条件関数でまとめて判定する。

## 7. ジャンカード
- 全45枚。
- 1回20円。
- 固定順。
- ダブりなし。
- 46回目以降は通常ガチャを回せない。
- 本編クリア条件と分離する。

保存例:
```json
{
  "cardsCollected": 18,
  "owned": [1,2,3],
  "nextCard": 19
}
```

## 8. 偽リセット／「もういちど」と実データの分離
- `glitch.*` フラグは演出の進行だけを管理する。
- 偽データ消失演出で `localStorage.clear()` 等を絶対に呼ばない。
- 序盤／起動直後には偽セーブ消失を使わない。
- **終盤には偽データ消失／初期化表示を正式採用するが、見た目だけにする。**
- 偽リセット前に必要な進行を安全に保存する。
- 「もういちど」選択後はNo.18「はじまりのばしょ」の最終章用状態へ遷移する。
- 主人公・タロサ・ミレイは前の出来事を覚えている設定を保つ。
- 主要パーティ加入状態、必要装備、重要アイテム、ジャンカード取得情報は実データ上保持する。
- 演出上、一時的にUIへ表示しない情報があっても、内部データは消さない。
- 演出失敗時は正常画面へ戻せるフェイルセーフを用意する。

### 「もういちど」復帰時の最低保証
- `story.once_more_started` 相当の状態が有効
- No.18最終章用イベントへ入る
- 主人公／タロサ／ミレイが必要な状態で存在する
- 記憶継承を示すイベントが再生可能
- ジャンカードを含む収集情報が失われていない
- 1回目オープニングへ誤って戻って再実行しない

## 10. セーブ破損対策
- JSON parse失敗時に即上書きしない。
- version不一致時にmigrationまたは安全な警告処理へ回す。
- 開発用セーブリセットとゲーム演出を別機能にする。
- 開発用キー操作を本番ビルドに残す場合は誤操作しにくくする。
- 「もういちど」前後をQAの独立チェック項目にする。

## 11. エンディング状態
- 真の最終解決後、主人公とわたべが元世界へ帰る進行を保存できるようにする。
- ミレイとの別れイベント完了状態を管理する。
- 元世界で主人公がNPCに戻る最終真相開示の再生済み状態を管理できるようにする。
- エンディング後にどこから再開できるか／クリアデータをどう扱うかはTBD。

## 12. 禁止
- 演出のために実データを消す。
- 「もういちど」を新規セーブ／New Game扱いしてそれまでの状態を失わせる。
- 未定義フラグ名をSceneごとにその場で量産する。
- 表示名をフラグキーに使う。
- ジャンカード状態を本編進行フラグと混同する。
