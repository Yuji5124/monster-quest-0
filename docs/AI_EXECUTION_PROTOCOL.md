# Monster Quest 0 AI実行プロトコル

更新日: 2026-09-09

このファイルは、Claude Code / Codex / Phaser Game Agentが作業を開始・実行・完了報告する際の共通手順を定義する。

## 1. 作業開始前
必ず次を行う。
1. `docs/INDEX.md` を読む
2. `docs/DECISIONS.md` を読む
3. 対象機能の専門仕様書を読む
4. 対象ファイル / assets / dataの実在を確認する
5. 既存実装を読んでから変更する

## 2. 不明点の扱い
以下を区別する。
- 確定仕様
- 未確定仕様
- 実装上の自由裁量

未確定仕様を、AIの都合でゲーム設定として確定しない。

例：
- 未確定の敵HP → 勝手に正式値を決めない
- 未確定の宝箱位置 → マップ制作中の仮配置は可。ただし仕様確定として記録しない

## 3. 最小変更原則
1タスクで必要な範囲だけ変更する。

禁止：
- ついでの全面リファクタリング
- unrelated fileの大量整形
- 動いている構造の無目的な置換
- 新規フレームワーク導入

## 4. 1タスク1目的
良い例：
- 「はじまりのまちのNPC会話を実装」
- 「BattleSceneのタッチ操作を修正」

悪い例：
- 「ゲーム全体を改善」
- 「全部きれいにリファクタリング」

## 5. Phaser Game Agent
Game Agentはメイン制作基盤として積極的に使用する。
ただし、生成結果は必ず既存仕様・正式素材・フォルダ構成と照合する。

Game Agentが生成したという理由だけで正式採用しない。

## 6. 正式素材
正式素材が存在する場合：
- 再生成しない
- 別デザインへ置換しない
- パスを確認して使用する

見つからない場合：
- 勝手に似た素材で確定実装しない
- 仮素材の場合は明示する
- `ASSET_MANIFEST.md` と `CONTENT_MATRIX.md` に状態を反映する

## 7. テスト
実装後は `DEFINITION_OF_DONE.md` と `QA_SPEC.md` を参照する。

最低限：
- 起動
- 対象機能操作
- 前後の導線
- コンソール重大エラー
- iPhone想定UI
を確認する。

## 8. 仕様変更
実装中に仕様変更が必要になった場合：
- コードだけで勝手に確定しない
- 関連Markdownへ反映する
- `DECISIONS.md` と矛盾しないか確認する

重大なゲーム設定変更は人間判断を優先する。

## 9. Git作業
- 機能単位で差分を小さく保つ
- 同じファイル群を複数AIが同時編集しない
- commit messageは内容が分かるものにする
- 大規模変更前後で動作確認する

## 10. 完了報告
最低限：
```text
変更:
- ...

確認:
- ...

未確認:
- ...

TODO:
- ...

仕様書更新:
- ...
```

「完了しました」だけは禁止。

## 11. 失敗時
問題が解決しない場合でも、作業を隠さない。
- 再現条件
- 試したこと
- 現在の仮説
- 変更したファイル
- 安全に戻せる状態か
を残す。

## 12. 最重要判断
高度さより完成速度。
Monster Quest 0に必要のない基盤開発をしない。
