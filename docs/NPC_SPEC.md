# モンスタークエスト0 NPC・会話仕様

最終更新: 2026-09-11 JST

## 1. 制作方針
NPC会話は全世界を一気に作らず、**物語の進行順に町・村ごとに整理して膨らませる**。

進行順:
1. はじまりのまち
2. ビーエのむら
3. レインランドのまち
4. レインランドじょう
5. ザボンのむら
6. いしのむら
7. かくれざと
8. 港町ダコハ
9. その他の拠点

最新方針として、町・村のサイズとNPC人数は従来案より**全体的に約半分程度へ圧縮**する。
既に作成済みの会話案は素材として活かすが、全員を実装する前提にはしない。

## 2. 現在の進捗
### はじまりのまち
**会話原案あり / 実装人数は再編対象**
- 旧案: NPC 12人
- 最新方針: 町サイズとNPC数を約半分程度へ圧縮
- 最初の町として世界の基本を自然に伝える
- 街道の交易・出発地点として生活感を出す
- 外へ出た後の会話変化案あり
- タロサ等、この時点で直接関係が薄い人物の話題へ偏らせない

### ビーエのむら
**会話原案あり / 実装人数は再編対象**
- 旧案: NPC 15人
- 最新方針: 小規模な村として人数を約半分程度へ圧縮
- 山に囲まれた村
- 薬草・林業など山の暮らし
- 行方不明の木こり救出事件
- 救出後の会話変化
- レインランドへ自然に誘導

### レインランドのまち
**会話原案あり / 実装人数は再編対象**
- 旧案: NPC 20人
- 最新方針: 城下町の規模そのものを縮小し、NPC数も約半分程度へ圧縮
- 水と商業の城下町としての生活感
- 周辺で起きている異変
- 王家に関する話
- ミレイに関する伏線
- いしのむらへの伏線
- ミレイの正体を加入前に直接ネタバレしない

### 次の制作
**レインランドじょうから続ける。**
ただし以降も「大人数で密度を出す」方式には戻さない。

## 3. NPCの基本ルール
- 村人・町人は基本2パターン程度の短い台詞
- 同じ人物でも進行により少し変化させてよい
- 全員を攻略ヒント役にしない
- 全員を主要人物の説明役にしない
- 子どもが読める短さを基本にする
- 大人が読むと地域同士の関係に気づける情報を混ぜる
- FC〜初期SFC風に、短く印象に残る言い回しを優先
- 固有名詞・アイテム・魔法は正式採用済みのみ使用
- 未確定事項をNPCが事実として話さない
- 終盤の真相や特殊解決法を序盤で直接説明しない

## 4. 会話役割
1つの地域に偏らないよう配置する。

### 生活NPC
仕事、食べ物、天気、家族、商売、地形など。

### 地域説明NPC
周辺の町、村、城、洞窟などを自然に知らせる。

### 事件NPC
現在その地域で起きている困りごと・異変。

### 攻略ヒントNPC
次の目的地や敵の特徴を断片的に示す。
答えを全部言わない。

### 人物関係NPC
タロサ、ミレイ、王家など主要人物に関する話。
正体や重要設定は段階的に出す。

重要: 主要人物に興味がない普通の住民も必ず入れる。特にタロサ関連地域でも、住民全員がタロサのことを話す構成は禁止。

### 遊びNPC
攻略に関係なく記憶に残る変な一言、昔のRPGらしい余白。

## 5. 地域テーマ
### はじまりのまち
交易・出発・街道。説明過多にせず外へ出たくなる会話。

### ビーエのむら
山、薬草、林業、山道、洞窟、木こり。

### レインランドのまち
水、商業、城下町、王家、旅人、噂。

### レインランドじょう
王家・政治・ミレイに関係する中心地。
正体判明前の情報管理を厳密にする。

### ザボンのむら
狩り、自然、タロサに関係する地域。
タロサの過去を全員が説明する構成にしない。
タロサに関心が薄い住民や、普通に日常を送る住民を意識的に混ぜる。

### いしのむら
石・岩・地形由来の強い個性を会話にも反映。

### かくれざと
閉鎖性、秘密性。直接説明より住民の反応で雰囲気を作る。

### 港町ダコハ
港、交易、人・物・噂。船移動をゲームシステムにしなくても港文化は使う。

## 6. 制作密度
全地域を同じ密度で作らない。

特に丁寧にする:
- 物語の始まり
- 主要人物の人生が交差する場面
- 終盤 / エンディング

通常地域は短くても生活感と個性が伝わればよい。
NPC人数を増やすことを「作り込み」とみなさない。
詳細は `CREATIVE_DIRECTION.md`。

## 7. 攻略ヒント
ボス攻略をNPC1人が完全解説しない。
複数の断片を組み合わせて気づける構成を優先する。

例:
- 最近戻ってこない人がいる
- 変な魔法を使う敵がいる
- 昔ここに何があった
- 特定装備を持つ者だけ入れた
- 別の町で聞いた噂

## 8. 実装
NPC会話をSceneコードへ散在させず、データ + EventSystemで管理する。

参照:
- `DATA_CONTRACTS.md`
- `EVENT_SYSTEM_SPEC.md`
- `NAMING_CONVENTIONS.md`
- `MAP_FLOW_SPEC.md`

基本:
- `message`
- `setFlag`
- `addItem`
- `transfer`
- `startBattle`

進行フラグで会話variantsを切り替える。

## 9. NPC画像
基本NPCは `assets/characters/npc/` の正式素材を使用する。
実ファイル名は `ASSET_INDEX.md` / `asset_catalog.json` を確認する。

固有キャラクター化したNPCは確定時に意味のある内部IDへ変更する。

## 10. AI制作手順
1. `PROJECT_STATUS.md` を読む
2. `STORY_FLOW.md` / `MAP_FLOW_SPEC.md` でその地域までの進行を確認
3. 地域の生活・事件・他地域との関係を確認
4. まず必要最小限のNPC人数を決める
5. 生活 / 地域 / 事件 / 攻略 / 人物関係 / 遊びが偏っていないか確認
6. 基本2パターン程度の短い会話を作る
7. ヒント重複と主要人物話題の偏りを整理
8. 未確定事項・ネタバレを確認
9. データ化
10. 実機で会話テンポ確認

AIが独自に新しい重要設定、重要アイテム、王家設定、ボス設定を確定してはいけない。
