# モンスタークエスト0 NPC・会話仕様

最終更新: 2026-09-11 JST

## 1. 制作方針
NPC会話は物語の進行順に町・村ごとに整理する。

ただし現在は、**マップ規模・地域構成・NPC人数をもう一度考え直す段階**とする。
これまで作成した会話案は削除せず「会話素材」として保持するが、人数・配置・登場順・実装対象は確定扱いしない。

旧「町・村とNPC人数を約半分へ圧縮」案も検討履歴として残すが、現時点では固定ルールにしない。
最終的には、作品全体の目標プレイ時間 **初見約4時間30分 / 寄り道込み約5時間30分** と、各地域の役割・テンポを見ながら決める。

## 2. 現在の状態
### はじまりのまち
**会話原案あり / NPC構成・人数は再検討**
- 街道の交易・出発地点という地域性は維持
- 最初の町として世界の基本を自然に伝える
- 説明NPCばかりにしない
- 主人公の冒険に特別な関心がない住民も入れる
- 既存の大人数案・縮小案ともに素材扱い

### ビーエのむら
**会話原案あり / NPC構成・人数は再検討**
- 山に囲まれた村
- 薬草・林業など山の暮らし
- 木こり関連イベント案あり
- 既存会話は素材扱い

### レインランドのまち
**会話原案あり / NPC構成・人数は再検討**
- 水と商業の城下町
- 王家・ミレイにつながる地域
- 生活感と噂のバランスを再設計する
- 既存会話は素材扱い

### レインランドじょう
**会話原案あり / NPC構成・人数は再検討**
- 王家・政治・ミレイに関係する中心地
- 城の規模とマップ導線を決めてからNPCを再配置する

### ザボンのむら
**会話原案あり / NPC構成・人数は再検討**
- 狩り・自然・タロサに関係する地域
- タロサの話題へ偏らせない
- タロサに関心が薄い、またはほぼ知らない住民もいる
- 既存会話は素材扱い

## 3. NPCの基本ルール
- 村人・町人は短く読みやすい台詞を基本とする
- 同じ人物でも進行により会話変化を持たせてよい
- 全員を攻略ヒント役にしない
- 全員を主要人物の説明役にしない
- 主人公たちに興味がないNPCも自然に存在させる
- 子どもが読める短さを基本にする
- 大人が読むと地域同士の関係に気づける情報を混ぜる
- FC〜初期SFC風に、短く印象に残る言い回しを優先する
- 固有名詞・アイテム・魔法は正式採用済みのみ使用する
- 未確定事項をNPCが事実として話さない
- 終盤の真相や特殊解決法を序盤で直接説明しない

## 4. 会話役割
1つの地域に偏らないよう配置する。
ただし役割ごとの人数比率はまだ固定しない。

### 生活NPC
仕事、食べ物、天気、家族、商売、地形など。

### 地域説明NPC
周辺の町、村、城、洞窟などを自然に知らせる。

### 事件NPC
現在その地域で起きている困りごと・異変。

### 攻略ヒントNPC
次の目的地や敵の特徴を断片的に示す。
答えを全部言わない。

### 人物関係NPC
タロサ、ミレイ、王家など主要人物に関する話。
正体や重要設定は段階的に出す。

重要: **主要人物に興味がない普通の住民も必ず存在させる。**
特にタロサ関連地域でも、住民全員がタロサを話題にする構成は禁止。

### 遊びNPC
攻略に関係なく記憶に残る変な一言、昔のRPGらしい余白。

## 5. 地域テーマ
### はじまりのまち
交易・出発・街道。説明過多にせず外へ出たくなる会話。

### ビーエのむら
山、薬草、林業、山道、洞窟、木こり。

### レインランドのまち
水、商業、城下町、王家、旅人、噂。

### レインランドじょう
王家・政治・ミレイに関係する中心地。
正体判明前の情報管理を厳密にする。

### ザボンのむら
狩り、自然、タロサに関係する地域。
タロサの過去を全員が説明する構成にしない。

### いしのむら
石・岩・地形由来の強い個性を会話にも反映。

### かくれざと
閉鎖性、秘密性。直接説明より住民の反応で雰囲気を作る。

### 港町ダコハ
港、交易、人・物・噂。船移動をゲームシステムにしなくても港文化は使う。

## 6. 制作密度
全地域を同じ密度で作らない。

特に丁寧にする:
- 物語の始まり
- 主要人物の人生が交差する場面
- 終盤 / エンディング

通常地域は短くても生活感と個性が伝わればよい。
NPC人数を増やすことを「作り込み」とみなさない。
同時に、単純に人数を半分にすることも目的にしない。

**必要な人物だけを置き、地域の役割とプレイテンポから最終人数を決める。**
詳細は `CREATIVE_DIRECTION.md`。

## 7. 攻略ヒント
ボス攻略をNPC1人が完全解説しない。
複数の断片を組み合わせて気づける構成を優先する。

例:
- 最近戻ってこない人がいる
- 変な魔法を使う敵がいる
- 昔ここに何があった
- 特定装備を持つ者だけ入れた
- 別の町で聞いた噂

## 8. 実装
NPC会話をSceneコードへ散在させず、データ + EventSystemで管理する。

参照:
- `DATA_CONTRACTS.md`
- `EVENT_SYSTEM_SPEC.md`
- `NAMING_CONVENTIONS.md`
- `MAP_FLOW_SPEC.md`

基本:
- `message`
- `setFlag`
- `addItem`
- `transfer`
- `startBattle`

進行フラグで会話variantsを切り替える。

## 9. NPC画像
基本NPCは `assets/characters/npc/` の正式素材を使用する。
実ファイル名は `ASSET_INDEX.md` / `asset_catalog.json` を確認する。

固有キャラクター化したNPCは確定時に意味のある内部IDへ変更する。

## 10. AI制作手順
1. `PROJECT_STATUS.md` を読む
2. `STORY_FLOW.md` / `MAP_FLOW_SPEC.md` でその地域までの進行を確認
3. 地域の生活・事件・他地域との関係を確認
4. **マップ規模と地域の滞在時間を確認してから必要NPCを決める**
5. 生活 / 地域 / 事件 / 攻略 / 人物関係 / 遊びが偏っていないか確認
6. 短い会話を作る
7. ヒント重複と主要人物話題の偏りを整理
8. 未確定事項・ネタバレを確認
9. データ化
10. 実機で会話テンポ確認

現段階では、AIが旧NPC人数や「半分」という数値を自動的に採用してはいけない。
AIが独自に新しい重要設定、重要アイテム、王家設定、ボス設定を確定してはいけない。
