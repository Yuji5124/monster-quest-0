# Monster Quest 0 開発ワークフロー

更新日: 2026-09-09

## 1. 基本方針
AI実装80% / 人間による視覚調整20%。

AIに大枠を作らせ、人間は見た目と遊び心地の最終調整へ集中する。

## 2. 標準フロー
1. GitHubの仕様書を更新する
2. Claude Codeが関連仕様書を読む
3. Phaser Game Agentを使って実装する
4. ブラウザでプレイ確認する
5. 人間がマップ・キャラクター・UIを視覚調整する
6. Claude Codeが修正を反映する
7. 節目でCodexがレビュー / QAを行う
8. 問題なければ次のエリアへ進む

## 3. 実装前に必ず読むファイル
- `docs/PROJECT_OVERVIEW.md`
- `docs/DECISIONS.md`
- 作業対象の専門仕様書

## 4. Vertical Slice優先
最初に以下を通しで完成させる。

タイトル
→ はじまりのまち
→ フィールド
→ ザコ戦
→ レベルアップ
→ 小ダンジョン
→ ボス
→ セーブ / ロード
→ iPhone Safari確認

この区間が製品版品質になるまで、全マップを量産しない。

## 5. マップ制作
- AIで地形・建物・当たり判定・イベント配置まで大枠を作る
- 人間が木、道、建物、装飾、余白などを最終調整する
- 基本タイルセットを再利用する
- 地域固有タイルは必要になった分だけ追加する
- 見た目のためだけに独自マップエディタを開発しない

## 6. キャラクター・画像
- 正式素材を最初から使用する
- 主人公、タロサ、ミレイの外見をAIが勝手に変更しない
- NPCは基本セットから差分を作る
- モンスターは原資料のデザインを優先する
- 不足素材だけ追加制作する

## 7. Claude Codeの役割
- メイン実装
- Phaser Game Agent利用
- システムの一貫性維持
- 正式素材組み込み
- 新規エリア追加
- イベント実装

同一機能をCodexと同時並行で大改修しない。

## 8. Codexの役割
節目で以下を重点確認する。
- iPhone Safari
- タッチ操作
- 画面サイズ
- マップ遷移
- イベント二重発火
- 戦闘不能 / 全滅
- セーブ / ロード
- 進行不能
- 画像読み込み
- メモリ / FPS

## 9. Astra
基本システム完成後の量産フェーズで使用する。

並列化例：
- Claude Code A：新しい町
- Claude Code B：新しいダンジョン
- Codex A：戦闘 / セーブQA
- Codex B：iPhone検証

同じファイル群を複数エージェントへ同時に編集させない。

## 10. 素材制作ルール
先に全素材を作らない。

実装中に不足が判明
→ ChatGPTで仕様 / 画像を作る
→ assetsへ追加
→ Claude Codeが組み込む

このループを基本とする。

## 11. 完成判定
「素材数」ではなく「製品版品質で何分遊べるか」を進捗指標にする。
