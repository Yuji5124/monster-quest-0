# モンスタークエスト0 終盤バグ・偽異常演出仕様

最終更新: 2026-09-11 JST

## 1. 基本方針
- 世界の**本格的な**バグ演出は序盤・中盤では多用しない。
- ただし現行オープニングでは、**「はじめから」直後に約5秒の短い制御された異常演出を1回だけ使用する。**
- この導入異常は、世界崩壊を見せる本格バグではなく、後から意味が分かる最初の違和感として扱う。
- その後の序盤〜中盤は「普通の昔ながらのRPG」として十分に成立させる。
- 終盤に入ってから、世界そのものの異常を段階的に強める。
- 実際のプログラム障害ではなく、すべて制御された演出として実装する。
- プレイヤーの実セーブデータやカード取得情報は絶対に破損させない。

## 2. オープニングの約5秒異常
正式骨格:
1. タイトル
2. 「はじめから」
3. 約5秒の短い異常画面
4. No.18「はじまりのばしょ」夜版へ正常遷移
5. 主人公が焚き火のそばで目覚める

使用可能:
- 一瞬の画像崩れ
- 短い文字ノイズ
- 音の途切れ / ノイズ
- 別画面断片が混ざったように見える演出

禁止:
- 本当のフリーズ
- 本当のエラー
- 長時間の操作不能
- 真相説明テキスト
- 最終戦級の大規模崩壊
- 偽セーブ消失

裏設定上、この約5秒には**主人公の元いた別のモンクエ世界からMQ0へ迷い込む瞬間の断片**を含める。初見でそれと分からないようにし、エンディング最終部で元世界を正常表示して回収する。

導入異常の最終デザイン・正確な秒数は `OPENING_SPEC.md` / `TBD_REGISTRY.md` に従う。

## 3. 序盤ではリセット／偽セーブ消失を使わない
タイトル直後・「はじめから」直後・通常起動時に偽「ぼうけんのしょが きえました」演出を入れない。

旧仕様の「ゲーム起動時に偽セーブ消失 → 数秒後に『……まだ おわっていない』」は現行オープニングでは不採用。

ただし、**終盤の「もういちど」へ入る直前には、データが消えた／初めからになったように見せる偽リセット表現を正式採用する。**

終盤の偽リセットでも以下を守る:
- LocalStorage等の実保存データを削除しない。
- セーブ破損を模倣する場合も見た目だけにする。
- 本物のエラー状態へ遷移させない。
- 必ず正常状態へ復帰できる。
- 主人公・タロサ・ミレイの記憶継承状態、パーティ情報、重要進行、ジャンカード取得情報は保持する。

## 4. 終盤での段階的異常
想定プレイ時間は**初見約4時間30分 / 寄り道込み約5時間30分**。
異常演出は固定時間ではなく、物語上の終盤フラグ以降で管理する。

### 初期異常
- NPC文章の一部が一瞬乱れる。
- BGMが一瞬止まる／音が欠ける。
- マップチップが一瞬だけ別画像になる。
- 一度見たはずの場所に小さな違和感が出る。

### 中程度
- 敵名の一部が文字化けする。
- 主人公やNPCのドット絵が一瞬乱れる。
- NPCが一時的に二重表示される。
- メニューに一瞬だけ `？？？` が現れる。
- 画面の一部だけ座標がずれる。

### 強い異常
- 画面が一瞬暗転する。
- BGMが停止する。
- 画面の一部が崩れる。
- 意味不明な文字列が混ざる。
- 最終地点がFC時代のバグ画面のように不安定に見える。

## 5. オロチゾンビ1回目〜「もういちど」の正式ギミック
オロチゾンビは裏ボスとして扱い、その1回目から「もういちど」へ入る流れを裏ワザとして位置づける。

基本シーケンス:
1. オロチゾンビ1回目。
2. 通常の強さだけでは解決できない状態になる。
3. 戦闘中または直後に画面がバグる。
4. 通常操作では進めない異常状態になる。
5. 「フーフー」を連想させる演出／入力を挟む。
6. データが消えた／初めからになったように見せる。
7. ゲームがオープニング／タイトル側へ戻ったように見える。
8. 「もういちど」という選択肢が現れる。
9. 選択するとNo.18「はじまりのばしょ」へ遷移する。
10. 主人公・タロサ・ミレイらは前の出来事を覚えており、仲間も存在している。
11. ここからわたべ参加を含む本当の終盤へ進み、オロチゾンビ再戦につながる。

「もういちど」はNew Game / 周回開始ではなく、**同一セーブ内の最終章進行**として扱う。

※具体的な答えや最終解決方法は公開用資料には書かない。

## 6. 導入と終盤の関係
- 導入の約5秒異常は、主人公が元世界からMQ0へ移動した最初の断片。
- 終盤では、その最初の違和感が世界の混線・主人公の出自と意味的につながる。
- 「もういちど」で冒頭と同じ焚き火へ戻すことで、始まりと終盤を同じ場所で結ぶ。
- 同じ演出を単純コピーせず、終盤の方が明確に規模・意味・危機感が大きい状態にする。
- エンディングで元世界を正常表示し、冒頭5秒の崩れた断片と対応させる。

## 7. 記憶継承の見せ方
- 主人公・タロサ・ミレイが「もういちど」前の出来事を覚えていることは固定。
- 長い理屈説明より、短い台詞・反応・行動で示す。
- 子どもには「最初に戻ったけど、みんな覚えている」で理解できればよい。
- 記憶が残った厳密な世界設定上の仕組みはTBD。
- プレイヤー本人やセーブデータを登場人物が直接語る説明にはしない。

## 8. 「たびのあいことば」
- 旧名称「ふっかつのじゅもん」は使用しない。
- 正式名称は **「たびのあいことば」**。
- タイトル画面の機能名も「たびのあいことば」に統一する。
- パッケージ／カセットの謎解き要素と関連づける場合も、公開仕様では答えそのものを記載しない。

## 9. パッケージ・カセットとの連動
- 黒箱／黒カートリッジを基本デザインとする。
- カセット表面の剣・宝石・星・数字などを終盤の入力順を示す謎に利用する。
- 裏面には「たびのあいことば」のヒントを置く。
- ジャンカード総数は45枚の現行仕様に合わせる。
- 普段見ていたパッケージ／カセット自体が終盤で攻略情報になる構造を狙う。

## 10. 発生回数
- 導入の約5秒異常は1回。
- 序盤〜中盤では本格異常を多用しない。
- 小さな終盤異常は3〜5回程度を目安とする。
- 最終地点／「もういちど」前後では演出密度を上げてよい。

## 11. 絶対に起こさないこと
- 本当のセーブデータ破損
- 本当のフリーズ
- 長時間の操作不能
- 進行不能
- 意図しない無限ループ
- ジャンカード取得情報の消失
- ブラウザ／iPhone上で本当のエラー画面を出して復帰不能にすること

## 12. ストーリー上の役割
- バグは単なるギャグではなく、世界の混線と主人公の出自につながる物語上の伏線として使う。
- 異なるモンクエ作品／バージョン由来の敵が同居することも同じ世界構造に接続する。
- 異常に強い終盤存在は、複数世界の重なりと意味的に結びつける。
- 最後は通常の強さだけでは解決できない構造へつなげる。
- わたべの役割や最終解決の詳細は内部設定として扱い、公開用資料では伏せる。

## 13. 実装
- バグ演出のON/OFFは進行フラグで制御する。
- 導入異常と終盤異常を別イベント / 別強度で管理する。
- 画面ノイズ、座標ずれ、文字化け、音停止などを個別の演出関数として実装する。
- 実エラーと演出エラーを混在させない。
- Phaser側で異常演出を終了後、必ず既知の正常状態へ復帰できるようにする。
- 導入異常終了後はNo.18夜版へ正常遷移する。
- 「もういちど」後はNo.18の最終章用状態へ正常遷移する。
- セーブ関連は `SAVE_FLAG_SPEC.md` を参照する。
